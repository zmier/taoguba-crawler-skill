# 淘股吧实盘比赛报单采集

给定淘股吧作者 ID，从个人博客的“实盘比赛”栏目取得当时可见的赛事、逐日申报与原图。平台对已结束赛事只展示获荣耀称号的比赛，因此目录条数表示本次可见场次。作者案例保存快照、阅读页与分析；采集器和来源规则维护在本 Skill。

## 入口与续跑

使用 SMK 项目 Python 环境。读取动态表需要 Node.js 能加载 Playwright，并能启动 Chrome。赛事详情沿用爬虫已有的淘股吧登录会话。运行目录为此 Skill 根目录。

```bash
python scripts/tgb_match_reports.py --user-id "$USER_ID" --output-dir "$MATCH_DIR"
```

可选 `--expected-username` 复核详情页昵称。全量流程依次执行目录、网页表格、相册导航、图片归档和核对。相同目录用于续跑该次快照。需要检查最新赛事或更新正在进行的赛事时，给新日期设置新的输出目录，再与旧快照比较。

| 阶段参数 | 读取与产物 |
|---|---|
| `--stage index` | 读取个人比赛目录，校验博客 ID、参赛者 ID 和赛事 ID，记录赛事名称、排名、时间和战绩链接。只有页面明确显示“暂无实盘比赛数据”才记录空目录 |
| `--stage tables` | 复用赛事目录，首次运行时先读取目录。保存每场可见的持仓、收益明细等栏目及其所有分页。战绩摘要保留平台原文和验证标识。遇到有记录的独立“交割单”栏目会保留原表、在 `unmapped_tabs` 标出赛事，覆盖状态为 `partial`，等待核实该版式的成交列和图片入口 |
| `--stage galleries` | 使用网页表格的“查看”入口，按赛事从最近一个入口同时向较新、较旧日期翻页。验证游标前进并保存两端结束回执 |
| `--stage archive` | 合并直接入口和双向相册，按来源登记每次配图，复用已落地的图片，产出 CSV、SQLite 和覆盖报告 |
| `--stage replay` | 使用已取得的目录、表格、相册分页及 SQLite 在本地重建索引，检查图像字节、来源与分页。可在快照副本运行 |

## 来源如何核对

1. 目录取自 `/user/blog/myspmath`，只跟随目标选手的 `/spmatch/gains/readInfo` 链接。详情页核验参赛者 ID 和比赛 ID。页面登录失效、结构异常、分页未完成时，保留已完成阶段，按爬虫的会话流程恢复。
2. 按网站实际渲染的表头逐页存档。持仓表的日期、日收益、账户金额和原图入口会跨多行合并；只在同一来源页的日期组内继承。保留同日同股同类的所有行、原始金额单位及 `--` 等缺值。收益表的一条记录对应一个“比赛 ID＋日期”。
3. 持仓列表没有股票行的日子仍可能有报单图。只从可见“查看”按钮进入相册，保留按钮、相册前后翻页及“暂无图片”的区别。平台明确返回错误码 10120 和“暂无图片”，或成功返回空页时，可记录该方向终点。其他错误或停滞游标需重试或报告缺口。遇到“解锁”记录日期，采集流程只使用已有访问权限。
4. 逐图保留比赛 ID、平台报单归属日、实际提交时间、组内图序、URL 和 SHA-256。补报可能发生在另一天。同一图片在不同赛事中重复提交时共享文件字节，各次出现仍有独立索引。字节不同的图片还可能经过加水印、裁切或重新压缩，需要看图判断内容重合。
5. 检查覆盖报告中的网页行数、收益日期、没有持仓行的收益日、相册补回日期、空入口、锁定日期、已取得的图片位置和唯一图片数。跨赛按日历日期另计。在收益和出入金吻合时记录重叠，保留不同场次的排名、区间及验证状态。赛事页面收益、券商截图收益和实际成交分别引用各自来源。
6. 程序退出成功且 `覆盖核对.json` 的 `state` 为 `visible-scope-complete` 表示本次可见范围归档完毕。缺图入口和没有可见入口的场次仍在报告中单列。图片获取失败会给出 `partial` 及非零退出码，重跑同一目录可重试。OCR、逐仓转录、重建交易或计算胜率按账户分析流程继续。

## 回归样本

不颜不语的三场历史比赛用于检验多行持仓、跨赛重叠、补报日期和相册补图。基准为 723 行持仓申报、337 条赛事日收益、433 个配图位置、353 张唯一图片。两处按钮返回“暂无图片”，双向相册比仅查持仓按钮多提供 105 个“比赛＋日期”。这些数字仅用于这个历史快照的回归。
